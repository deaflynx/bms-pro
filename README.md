# bms-pro.com.ua — новий сайт

Статичний сайт BMS Pro на Astro. Прилади біомеханічної стимуляції мʼязів,
виробник — ТОВ «УКРСИСТЕМС». Замінить наявний сайт на WordPress після узгодження.

**Прев'ю:** https://deaflynx.github.io/bms-pro/
**Обраний макет:** https://deaflynx.github.io/bms-pro/mockups/a/

## Що це дає порівняно з наявним сайтом

Заміри від 27.07.2026 проти живого сайту:

| | WordPress | Зараз |
|---|---|---|
| HTML головної | 689 948 Б | ~32 КБ |
| HTML `/services/` | 1 016 004 Б | — (замінено на 5 сторінок) |
| CSS + JS на сторінку | 18 + 22 запити | 2 CSS (~14 КБ), 1 JS |
| Сторонні запити при завантаженні | Google Fonts + плагіни | немає (шрифти локальні) |
| Вага сторінки, HTML+CSS+JS | ~710 КБ | 18–52 КБ |
| Структуровані дані JSON-LD | немає | на кожній сторінці |
| Сторінок з контентом | 3 | 20 |
| Сторінка на прилад | немає | 5 |
| `<iframe>` при завантаженні | — | 1 (карта Google на «Контактах», lazy) |

## Розробка

```bash
npm install
npm run dev          # http://localhost:4321/bms-pro/
npm run build
npm run preview
```

### Перевірки

```bash
npm run check            # astro check — типи, має бути 0 errors
npm test                 # 251 тест: юніти + перевірки готового dist/
npm run test:unit        # лише чисті функції
npm run test:build       # збірка + перевірки dist/
npm run og               # перегенерувати Open Graph зображення
npm run icons            # перегенерувати favicon.ico / favicon.png / apple-touch-icon
npm run fonts            # перезавантажити шрифти з Google Fonts у src/styles/fonts/

# адаптивність: 15 маршрутів × 3 ширини, overflow і розміри кнопок
npm run build
npx astro preview --port 4321 &
npm run test:responsive

# цілісність посилань
npx linkinator http://127.0.0.1:4321/bms-pro/ --recurse --skip 'youtube|ytimg|fonts\.g|google\.com/maps'
```

CI (`.github/workflows/deploy.yml`) виконує `check` → `build` → `vitest run` і
деплоїть на GitHub Pages лише за умови, що все пройшло.

## Як редагувати контент

Контент — у git, CMS немає.

| Що змінити | Де |
|---|---|
| Ціни, зони впливу, характеристики приладів | `src/content/products/*.md` |
| Текст паспорта, декларації, ТУ | `src/content/documents/*.md` |
| Питання та відповіді | `src/content/faq/*.md` |
| Опис приладу (250+ слів на сторінку) | текст під frontmatter у `src/content/products/*.md` |
| Телефони, адреса, номер декларації | `src/lib/site.ts` |
| Кольори й шрифти | `src/styles/tokens.css` |

Після зміни ціни в `src/content/products/*.md` вона автоматично оновлюється
на картці, у таблиці порівняння, на сторінці приладу та в `Product` schema —
джерело одне.

### Питання та відповіді

`models` у frontmatter питання вирішує, де воно показується:

- `models: []` — тільки на `/faq/`. Так позначені всі загальні питання
  (медичний виріб, гарантія, доставка, протипоказання). До цього вони
  дублювалися на всіх пʼятьох сторінках приладів і давали ~164 слова
  однакового тексту на кожній.
- `models: ['bms-quadro', 'bms-magnus']` — на `/faq/` **і** на сторінках
  названих моделей. Сюди йдуть тільки порівняння й питання про конкретну
  модель.

Кожна модель мусить мати щонайменше два власні питання — це перевіряє
`tests/unit/content.test.ts`.

### Структуровані дані

Усі вузли JSON-LD збирає `src/lib/schema.ts`. Компанія має один ідентифікатор —
`<site>/#org` (`organizationId()`): його носять і `Organization` у макеті, і
`LocalBusiness` на `/contacts/`, а `Product`, `DigitalDocument` та `Article`
посилаються на нього замість того, щоб повторювати назву. До 11.09.2026 `@id` не
було, і Google бачив дві різні компанії за однією адресою.

`SITE.sameAs` у `src/lib/site.ts` **порожній**. Це не список посилань, а заява
про тотожність — «ця сторінка і є ця компанія». Коли зʼявляться реальні профілі
(Facebook, Instagram, YouTube, сторінка на Prom чи Rozetka), їх треба додати
туди — решта підхопиться сама. Помилковий запис злиє бренд із чужою сторінкою,
тому порожньо краще, ніж навмання.

`logo` вказує на `/logo.png` (512×512, генерує `npm run icons`). Лого-локап
не годиться: його напис білий і зникає на світлому тлі панелі знань.

### Верхнє меню

`NAV` у `src/lib/site.ts` — це рядок меню. `/about/` і `/privacy-policy/`
навмисно лишаються тільки у футері: у смужці п'ять пунктів, більше не вміщується
в один рядок на 1100 px. Нижче 900 px меню ховається, навігація йде футером.

### Інтерактивна панель

`Instrument` рендериться **лише на `/how-it-works/`**. Зі сторінок приладів його
прибрано 11.09.2026 — на кожній він показував одну й ту саму демонстрацію й тягнув
за собою свій JS. Тип панелі на сторінці приладу лишається текстовим чіпом у герої
(`instrumentFor(d.indicator).label`).

### Таблиця порівняння

`ComparisonMatrix` рендериться **лише на головній**, у секції `#compare`.
Сторінки приладів і каталог ведуть на неї компонентом `CompareLink`, а
перехресні посилання між моделями дає смужка `.siblings` внизу сторінки
приладу. Раніше матриця стояла на семи сторінках і давала ~140 слів
дубля на кожній.

## Структура сторінок

```
/                                          Головна
/products/                                 Каталог, посилання на таблицю порівняння
/products/{bms-m,bms-pro,bms-nexus,bms-quadro,bms-magnus}/
/how-it-works/                             Метод, сфери застосування, кому корисно
/documents/                                Список наявних документів
/documents/bms-m/{passport,declaration,technical-conditions}/   (стосуються й BMS pro)
/documents/bms-quadro/passport/
/about/  /contacts/  /faq/  /privacy-policy/
/404                                       Своя сторінка помилки, noindex
```

Документи мають схему `/documents/<модель>/<тип>/` — масштабується до 12 сторінок,
коли зʼявиться документація на решту моделей.

## Потрібно від замовника

Перелічено за впливом на запуск.

1. **Окремі описи для кожної моделі.** Наявні тексти написані з фотографій і
   паспорта BMS m — їх треба перечитати й виправити. Чотири сторінки з однаковим
   текстом конкурують між собою в пошуку. **Головний блокер.**
2. **Підтвердити виведені дані** — кількість каналів та тип індикатора по кожній
   моделі, і чи Quadro дійсно для кабінету, а не для дому. Ці значення виведені
   з фотографій, а не надані.
3. **Паспорт, декларація і ТУ для Nexus і Magnus; декларація і ТУ для Quadro.**
   Документи BMS m поширюються й на BMS pro (у них зазначено «BMS (m, Pro)»);
   `/documents/` показує лише наявні документи, решта — на запит телефоном.
4. **Фотографії на однотонному тлі.** Усі наявні знімки зроблені на телефон на
   робочому столі. Для приладів за 24 000–83 000 ₴ це головне, що обмежує
   довіру. **BMS Quadro — найтерміновіше**, його фото читається як сірий
   3D-друкований прототип.
5. **Фото Олександра Бабака у нормальній роздільності** — наявне було 147×147 px
   і вилучене з репозиторію 10.09.2026 як невикористане; сторінка «Про нас» зараз без фото.
6. **Логотип у векторі (SVG)** — наявний растр 512×512, стоїть у шапці всіх
   сторінок.
7. **Власне відео українською** — за бажанням. Сторонній ролик прибрано з сайту
   07.09.2026 на прохання замовника.
8. **Перечитати політику конфіденційності.** Це юридичний текст; версія з
   WordPress описувала коментарі, реєстрацію, розсилку, Google Analytics і
   Facebook Pixel, яких на новому сайті немає, тому ці пункти видалено.

## Продакшен

Бойовий сайт https://bms-pro.com.ua/ живе на хостингу HestiaCP, перед ним —
Cloudflare. Деплой однією командою, потрібен SSH-доступ до акаунта хостингу:

```bash
npm run deploy   # SITE_URL=https://bms-pro.com.ua BASE_PATH=/ npm run build + rsync dist/ на сервер
```

Адресу сервера і каталог скрипт бере з `deploy/.env` (не в git):
`DEPLOY_HOST=user@host` і `DEPLOY_DOCROOT=/home/user/web/bms-pro.com.ua/public_html`.

- **Cloudflare кешує HTML** (Cache Everything, browser TTL 1 місяць), тож після
  деплою треба зробити *Purge Everything* у панелі Cloudflare, інакше відвідувачі
  бачать стару версію до місяця.
- **Редиректи 301** зі старих адрес WordPress (`/services/`, `/contact/`, `/shop/`,
  `/cart/`, `/checkout/`, `/my-account/`) — два шари. Astro генерує сторінки з
  миттєвим meta-refresh (працюють одразу після деплою). Додатково
  `deploy/nginx-redirects.conf` копіюється у `public_html/redirects.conf`: шаблон
  nginx хостингу підключає `public_html/*.conf` у блок `server`, і після
  перезавантаження nginx (будь-яка зміна вебдомену в панелі Hestia) це справжні
  301.
- `public/mockups/` на бойовий сайт не потрапляє — лише на GitHub Pages.
- WordPress-версію збережено на сервері поруч із `public_html` як
  `public_html.wordpress-2026-09-07`, база даних не чіпалась. Відкат — поміняти каталоги місцями. Тримати ще місяць.

`deploy/nginx-redirects.conf` також містить `error_page 404 /404.html` (інакше
nginx показує свою типову сторінку) і `301` з `/sitemap.xml` на `/sitemap-index.xml`.
Обидва вмикаються тільки після перезавантаження nginx.

Після перенесення: подати `https://bms-pro.com.ua/sitemap-index.xml` у Search
Console і перевірити редиректи.

## Шрифти й іконки

Шрифти не тягнуться з Google Fonts — `npm run fonts` завантажує 12 файлів woff2
(Oswald, Onest, JetBrains Mono × latin, latin-ext, cyrillic, cyrillic-ext) у
`src/styles/fonts/` і генерує `src/styles/fonts.css`. Усі три сімʼї змінні, тому
на кожну пару «сімʼя + підмножина» припадає один `@font-face` з діапазоном ваги.
Знак гривні ₴ живе в підмножині `cyrillic-ext`, не в `cyrillic`.

Іконки генерує `npm run icons` із `logo.webp`: Google Search не приймає WebP
як favicon, тому потрібні `favicon.ico`, `favicon.png` і `apple-touch-icon.png`.

Обидва набори закомічені — це вхідні дані збірки, а не її результат.
